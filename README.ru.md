# openchamber-agents

Установите расширение по [краткой инструкции](Установка.md), чтобы хранить и переключать наборы глобальных правил `AGENTS.md` в OpenChamber.

Русский | [English / 简体中文](README.md)

**AGENTS.md Manager** позволяет редактировать наборы правил, просматривать построчные различия перед активацией, создавать резервные копии и восстанавливать прежние версии. При активации расширение сохраняет исходный файл, выполняет атомарную запись и повторно читает результат для проверки. Компактный блок в разделе статуса работы показывает текущий набор.

Версия **0.1.6**. Дата проверки, указанная в оригинале: **2026-10-22**. Требуется OpenChamber **2.4.0 или новее**. Панель следует теме OpenChamber.

> **Интерфейс панели пока только на китайском.** В этой документации названия основных элементов приведены с переводом и исходной подписью, чтобы их можно было найти на экране. Перевод документации не меняет язык расширения.

## Возможности

- Библиотека наборов: создание, копирование, импорт, архивирование и экспорт.
- Построчное сравнение перед активацией, автоматическое резервное копирование и восстановление.
- Обнаружение внешних изменений, повреждения библиотеки и ошибок доступа вместо перезаписи без предупреждения.
- Нет фоновой службы, вызовов моделей, отправки сообщений в сеансы и сетевых запросов.
- Доступ только к `~/.config/opencode/AGENTS.md` и `~/.config/openchamber/agents-manager/**`.

## Установка и пути

### Установка из GitHub с поддержкой обновлений

В OpenChamber откройте **Настройки → Расширения → Добавить расширение** и вставьте:

```text
https://github.com/chenyuhao0628/openchamber-agents
```

Страница настроек проверяет обновления по полю `version` в корневом `package.json` репозитория. Если доступна новая версия, на карточке появляется действие «Обновить». Механизм обновления доступен только при установке по Git URL. При установке из папки или ZIP нужно вручную заменить установленную версию.

### Установка из папки для разработки

1. В каталоге расширения выполните:

   ```sh
   npm ci
   npm run typecheck
   npm test
   ```

2. Добавьте этот каталог через **Настройки → Расширения → Добавить расширение → Папка**.
3. Подтвердите заявленные области доступа:

   | Область доступа | Назначение |
   | --- | --- |
   | `~/.config/opencode/AGENTS.md` | Чтение и замена глобальных правил по действию пользователя |
   | `~/.config/openchamber/agents-manager/**` | Библиотека наборов, резервные копии и экспорт |

Файлы читает и записывает **сервер OpenChamber, к которому вы сейчас подключены**. При удалённом подключении эти пути относятся к серверу, а не к вашему компьютеру.

В этой версии пути фиксированы. Расширение не определяет пользовательский `XDG_CONFIG_HOME`, нестандартный каталог конфигурации OpenCode или файл Codex `~/.codex/AGENTS.md`. Если ваши правила находятся по другому пути, эта версия ими не управляет.

### Передача ZIP-архива другому пользователю

1. В каталоге расширения выполните `npm run share`.
2. Передайте полученный файл `dist/openchamber-agents-<версия>.zip`.
3. На принимающей стороне выберите ZIP через **Настройки → Расширения → Добавить расширение**. Распаковывать архив не нужно.

Штатный архив содержит китайскую инструкцию `安装说明.md` и полный `README.md`. В него входят только необходимые для установки манифест, две HTML-точки входа, два скрипта панели и два документа. Исходников, тестов и зависимостей в архиве нет. Добавление русских документов в репозиторий само по себе не меняет состав штатного архива.

### Совместимость и разрешения

Манифест задаёт минимальную версию OpenChamber `>=2.4.0` с запасом по совместимости. SDK для разработки закреплён на версии `2.0.3`. В оригинале указана локальная проверка на OpenChamber 2.4.0 / OpenCode v2.0.32. Версия SDK и версия OpenChamber различаются; объявленный диапазон совместимости не означает, что проверена каждая версия.

Расширение не имеет разрешений на фоновую службу, вызовы моделей, отправку сообщений в сеансы и сетевые запросы. Если OpenChamber сообщает о недостаточном доступе к файлам, проверьте заявленные области доступа в настройках расширения.

## Повседневная работа

### Открытие панели

Нажмите **«Наборы правил» (`规则方案`)** справа или выберите **«Глобальные правила → Управление» (`全局规则 → 管理`)** в разделе статуса работы. Оба входа открывают один и тот же редактор в боковой панели.

**В сеансе без проекта используйте значок справа.** В исходной версии OpenChamber 2.4.0 кнопка `管理` в разделе статуса работы не реагирует; см. [известные ограничения](#известные-ограничения).

При первом открытии полной панели текущий глобальный текст копируется в набор **«Существующие глобальные правила» (`现有全局规则`)**. Глобальный файл при этом не изменяется. Открытие одного лишь блока статуса не создаёт библиотеку.

### Черновики и сохранение

Действия **«Создать», «Копировать», «Импортировать» (`新建`, `复制`, `导入`)** создают черновик. Название и Markdown можно редактировать напрямую. Поддерживается импорт `.md` и `.txt`. Содержимое всегда обрабатывается как текст: HTML не отображается как разметка, правила не исполняются самим расширением.

Кнопка **«Сохранить набор» (`保存方案`)** обновляет только библиотеку. Доступны сочетания `⌘S` / `Ctrl+S`.

Если при переключении набора, создании или импорте есть несохранённые изменения, можно сохранить их и продолжить, отбросить изменения либо остаться в редакторе. Переключение вкладок и темы сохраняет черновик. После закрытия или перезагрузки панели восстановление черновика не гарантируется: сначала сохраните его.

### Активация набора

1. Нажмите **«Предпросмотр активации» (`预览启用`)**, чтобы сравнить набор с актуальным глобальным файлом построчно.
2. Проверьте различия и подтвердите активацию.

После подтверждения расширение создаёт резервную копию исходного текста, ещё раз проверяет файл, выполняет атомарную запись и повторно читает результат. При совпадении содержимого запись не нужна. Перед записью пустого текста появляется явное предупреждение об очистке файла.

### Управление наборами

Раздел **«Управление наборами» (`方案管理`)** позволяет архивировать и восстанавливать наборы, показывать архивные записи и экспортировать текст. Архивирование обратимо. Набор, совпадающий по содержимому с текущим глобальным файлом, архивировать нельзя.

Экспорт сохраняется в каталоге данных подключённого сервера; путь отображается в интерфейсе.

### Восстановление резервной копии

1. В разделе **«Резервные копии» (`备份`)** выберите запись по времени создания и просмотрите исходный текст.
2. Выберите **«Предпросмотр восстановления → Подтвердить восстановление» (`预览恢复 → 确认恢复`)**.

Перед восстановлением расширение также сохраняет резервную копию текущего файла.

### Что означает статус

Вверху отображается набор, совпадающий с фактическим содержимым файла, либо состояние вроде «Нет совпадений среди сохранённых наборов» или «Глобальные правила пусты».

**Этот статус не подтверждает, что сеанс уже загрузил правила.** Правила проекта по-прежнему загружает сам OpenCode по своему механизму. Поведение перезагрузки правил в уже открытых сеансах не проверено; после активации рекомендуется проверить результат в новом сеансе.

## Данные и устранение неполадок

```text
~/.config/openchamber/agents-manager/
  library.json          # version: 1; тексты наборов и метаданные
  backups/<время-UUID>.json
  exports/<ID-набора>.md
```

### Хранение и ограничения размера

- Данные сохраняются в заявленном файловом каталоге, а не в хранилище SDK, которое очищается при удалении расширения. Само расширение не удаляет эти файлы при деинсталляции. Автоматической ротации резервных копий нет; перед очисткой сохраните нужные версии.
- Текст набора ограничен 100 000 символов, название: 60 символами. Допускается до 100 наборов, включая архивные. Сериализованная библиотека ограничена 1 500 000 символов. Если существующие правила слишком велики для первого импорта, расширение сообщает об ошибке и оставляет исходный файл без изменений.
- Список показывает последние 50 резервных копий из результата чтения каталога, полученного от OpenChamber. Копия содержит полный исходный текст; действует ограничение SDK в 2 000 000 символов на файл. **Если резервное копирование не удалось, запись глобальных правил блокируется.**
- Если исходного файла нет, расширение создаёт его. В SDK отсутствует интерфейс удаления файлов, поэтому восстановить состояние «файл не существует» нельзя.

### Сравнение и конфликты

- Различия вычисляются построчно. Очень большие изменения отображаются как замена целого блока; предпросмотр ограничен 400 строками. Пропущенная часть явно обозначается. Для полной проверки можно вернуться в редактор или просмотреть исходный текст резервной копии. Различия CRLF/LF показываются отдельно; сохранение не преобразует окончания строк намеренно.
- Ошибки доступа, формата или чтения не трактуются как пустая библиотека. При повреждении библиотеки исходный файл сохраняется, а пользователю показывается ошибка. Внешнее редактирование делает предпросмотр недействительным: нужно вернуться и открыть его заново. При конфликте библиотеки действие **«Перечитать» (`重新读取`)** сохраняет черновик, после чего можно решить, сохранять ли его с учётом нового состояния.
- SDK записывает временный файл и атомарно заменяет целевой, но не предоставляет операции сравнения и замены (compare-and-swap) или блокировки между окнами. Повторная проверка перед записью и чтение после неё выявляют распространённые конфликты, но **не гарантируют отсутствие потерянных изменений при одновременной записи из нескольких редакторов**. После ошибки или тайм-аута сначала перечитайте фактическое состояние. Не повторяйте перезапись без проверки.

### Конфиденциальность

Наборы, резервные копии и экспорт содержат полный текст правил. Действуют файловые разрешения текущего сервера; расширение не добавляет шифрование и не выполняет `chmod`. **Не записывайте учётные данные и секреты в правила.**

### Ошибка `Extension operation failed.` при открытии или повторном чтении

В оригинале описано воспроизведение ошибки 2026-10-19 на локальной установке OpenChamber 2.4.0. Если путь текущего проекта содержит китайские или другие символы вне Latin-1, OpenChamber помещает путь без преобразования в заголовок запроса `x-opencode-directory`. Метод браузера `Headers.set` выбрасывает исключение ещё до отправки запроса, а мост сообщений возвращает только общее английское сообщение об ошибке.

Путь проекта добавляется и при доступе к глобальным файлам, поэтому ошибка затрагивает их тоже. **Сама ошибка не означает повреждения файла правил.** Ранее загруженные название и текст могут остаться на экране: это не подтверждает успех текущего чтения.

Начиная с версии 0.1.5 расширение указывает, что именно не удалось обработать: глобальные правила, библиотеку или резервную копию. При описанной проблеме совместимости оно показывает причину на китайском. Если повторное чтение основных файлов не удалось, уже загруженное содержимое и черновик сохраняются с пометкой, что это результат предыдущего чтения. После ошибки записи интерфейс не предлагает бездумно повторять отправку. В журнал попадают только тип ошибки и категория символов в пути, без самого пути и текста правил.

**Улучшены диагностика и сообщения, но проблема OpenChamber с такими путями остаётся.** Файловые методы SDK 2.0.3 не позволяют расширению переопределить текущий каталог или заголовок запроса.

Временное решение: откройте **«Наборы правил» (`规则方案`)** через значок справа в сеансе без проекта либо используйте существующий проект без таких символов в пути. Переименовывать проект или менять файл правил не требуется. В сеансе без проекта используйте именно боковой значок: ограничение кнопки `管理` описано [ниже](#известные-ограничения).

2026-10-19 автор исходной документации отправил в основной проект [Issue #5179](https://github.com/openchamber/openchamber/issues/5179) с тестовым расширением, примерными путями и универсальным сценарием воспроизведения. Он связан с [Issue #5180](https://github.com/openchamber/openchamber/issues/5180) о навигации без проекта. Настоящие правила, пути проектов, журналы и снимки экрана не отправлялись. Улучшение сообщений в расширении не означает исправления ошибки в OpenChamber.

Основание исходной диагностики: проверка без внесения изменений официального [файлового прокси v2.4.0](https://github.com/openchamber/openchamber/blob/v2.4.0/packages/ui/src/lib/guests/files.ts), [моста сообщений](https://github.com/openchamber/openchamber/blob/v2.4.0/packages/ui/src/lib/guests/host-bridge.ts) и исходных ресурсов локальной установки. При проверке формирования заголовка на тестовых путях отсутствие каталога и ASCII-путь обрабатывались успешно, а китайский путь вызывал `TypeError` до сетевого вызова. По данным оригинала, установленный OpenChamber не изменялся; проверки содержимого настоящего глобального файла, библиотеки и резервных копий до и после перезагрузки и чтения дали одинаковый результат.

## Известные ограничения

- В сеансе без проекта кнопка **«Управление» (`管理`)** в разделе статуса работы может не реагировать. Используйте значок **«Наборы правил» (`规则方案`)** справа.
- Если путь проекта содержит китайские или другие символы вне Latin-1, файловые запросы OpenChamber могут завершаться ошибкой. Используйте сеанс без проекта либо проект без таких символов в пути.

## Разработка и проверка

В каталоге расширения выполните:

```sh
npm ci
npm run typecheck
npm test
npm run preview
```

`npm test` сначала собирает `panel/main.js` и `panel/section.js`, затем запускает тесты Node.

`npm run share` сначала собирает скрипты панели, затем создаёт `dist/openchamber-agents-<версия>.zip` с учётом ограничений установки ZIP в OpenChamber. Скрипт повторно читает архив, проверяет состав, CRC и содержимое, после чего выводит контрольную сумму.

### Безопасный предпросмотр

Скрипт предпросмотра раздаёт собранные файлы расширения только на `127.0.0.1`. Все файловые интерфейсы имитируются на вымышленных данных в памяти браузера. **Настоящие глобальные файлы не читаются.**

Случайный порт выводится в терминале. Задать конкретный порт можно переменной `PREVIEW_PORT`.

Предпросмотр поддерживает переключение темы, ширины 400/280 px и раздела статуса, а также имитацию внешних изменений, сбоя резервного копирования и недостаточных разрешений.

| Параметр URL или действие | Что проверяется |
| --- | --- |
| `state=empty`, `state=denied`, `state=corrupt` | Пустое состояние, отказ в доступе или повреждённая библиотека при запуске |
| `directory=unicode` или «Имитировать китайский путь» (`模拟中文目录`) | Ошибка заголовка файлового запроса |
| `surface=status&directory=none` | Ошибка навигации исходной версии OpenChamber в сеансе без проекта |

Предпросмотр воспроизводит исходное поведение. Его результаты **не доказывают исправление в реальном OpenChamber**.

| `src/core/` | Проверка наборов, этапы транзакций сохранения, алгоритм сравнения |

### Изменения интерфейса и прежние проверки

В версии **0.1.6** высота строки состояния уменьшена до 20 px, убран дополнительный верхний отступ нижней панели, а заявленная в манифесте высота изменена с 64 до 56 px. Высота строк, иерархия текста и расположение действий приведены к виду встроенного расширения подсказок.

В версии **0.1.1** используется поддерживаемый OpenChamber значок пера `quill-pen`. Сводка статуса работы стала двухстрочной: слева подпись и время чтения, справа название набора и действие. Убраны повторяющиеся пояснения и стандартные отступы абзацев. Новые разрешения не потребовались.

В оригинале также зафиксирована проверка установки и включения расширения в среде автора: первый набор совпадал с исходным глобальным файлом, а проверка интеграции не изменяла настоящие глобальные правила. Это историческая запись, а не подтверждение состояния вашей установки.
